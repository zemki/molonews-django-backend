# Importing articles and events

Content comes from **sources**. Each source belongs to an organization and has a
type that determines how it is imported. Sources are managed in the admin
(`/oldadmin/content/source/`) or by editors in newadmin.

## Source types

| Type | Content | Imported by | How |
|---|---|---|---|
| `rss` | Articles | `import_articles` | RSS/Atom feed; optional per-source parser (`generic`, `wordpress`, `events`) |
| `json-event` | Events | `import_articles` | JSON feed in the event format below |
| `xml-event` | Events | `import_articles` | XML feed |
| `ics` | Events | `import_articles` | iCalendar feed |
| `ai-article` | Articles | `import_html_articles` | Website without feed; an import script is generated by the local language model |
| `html-event`, `ai-event` | Events | `import_html_events` | Website without feed; generated import script. `ai-event` sources can also receive files via the upload API |
| `local` | Both | – | Content created in the apps or in newadmin |

### Source settings that decide what appears in the apps

| Field | Effect |
|---|---|
| `active` | New sources are **inactive**. Importers skip inactive sources; `import_articles` then reports "0 Articles imported". |
| `default_published` | Off: imported entries are saved unpublished and wait for review in the admin. On: they are published immediately. |
| `area` | Areas assigned to imported entries. Devices only see entries from their areas. |
| `default_tags` | Topics assigned to imported entries (see also `IMPORT_FALLBACK_*_TAG_ID`). The apps filter by topic. |

Devices that are created after an organization exists follow it automatically.
Existing devices get a new organization with
`python manage.py add_organization_to_all_users <organization-id>`.

Run the importers regularly (see `deploy/crontab.example`):

```bash
python manage.py import_articles        # feeds
python manage.py import_html_articles   # generated article scrapers
python manage.py import_html_events     # generated event scrapers
```

## Generated import scripts

For sources of type `ai-article`, `html-event` and `ai-event` without a script,
the importer fetches the page, removes scripts and styles and asks the language
model (`LLM_CODEGEN_MODEL`, default `LLM_MODEL`) to write a standalone Python
script. The script is checked (syntax, required function, allowed imports and
calls, see below), stored in `IMPORT_SCRIPTS_DIR` as `source_<id>_<kind>.py` and
referenced in the source's `import_script` field.

Interface of a generated script:

```python
def scrape_articles_from_website(url: str) -> list[dict]:
    # keys: article_title, article_link (required), article_abstract,
    #       article_content, article_date (ISO 8601), article_image
    ...

def scrape_events_from_website(url: str) -> list[dict]:
    # keys: event_title, event_start_date (required, ISO 8601), event_end_date,
    #       event_content, event_link, event_image, event_ticket_link,
    #       event_categories (list), location, street, zip_code, town,
    #       latitude, longitude
    ...
```

`gpt-oss:120b` produces noticeably better scrapers than `gpt-oss:20b`.

### Approval

The page HTML comes from a third-party website and may contain instructions
aimed at the language model (prompt injection). A generated script is therefore
**never executed until a superuser has approved it**:

1. The importer (cron or the button *Script neu generieren* in the Django admin)
   generates the script and marks the source with
   "Script erzeugt – wartet auf Freigabe im Admin". Nothing is executed.
2. A superuser opens the source in the Django admin (`/oldadmin/content/source/<id>/change/`),
   reads the code under *Import-Script prüfen* and clicks *Script freigeben*.
   The SHA-256 hash of exactly the displayed code is stored in
   `Source.import_script_approved_hash`.
3. On the next run the importer executes the script, writes a preview of the
   extracted entries to `MEDIA_ROOT/articlepreview/` or `MEDIA_ROOT/eventpreview/`
   and, for active sources, imports the entries.

The approval becomes invalid when the script file changes or when the source's
`link` or `type` changes; the source is then skipped until it is approved again.
*Import-Script löschen* removes script, preview and approval, so a new script is
generated on the next run. All three actions are POST-only.

Before saving and before every run, scripts are additionally checked for
forbidden constructs: only `requests`, `bs4`, `feedparser`, `dateutil`, `lxml`,
`chardet` and a small set of standard-library modules (`re`, `json`, `datetime`,
`time`, `html`, `urllib.parse`, `email.utils`, …) may be imported; `open`,
`eval`/`exec`, `getattr`, access to `os`/`sys`/environment variables and dunder
attributes are rejected. This check is not a sandbox – reading the code before
approving it is the actual safeguard. Run the importer as an unprivileged user.

You can also write or edit scripts by hand in `IMPORT_SCRIPTS_DIR`; they must
implement the function above, pass the check and be approved again after every
change.

### Source URLs

Links of sources are fetched by the server. New or changed links in the
editorial interface and the Django admin, and the pages fetched for script
generation, must resolve to public addresses; `localhost`, private networks
(`10.0.0.0/8`, `192.168.0.0/16`, …) and link-local addresses such as
`169.254.169.254` are rejected. For local development set
`ALLOW_PRIVATE_IMPORT_URLS=true`.

## JSON event format

Used by `json-event` feeds, the upload API and the command `import_events_json`.
One entry per date:

```json
[
  {
    "event_title": "Open-air concert",
    "event_content": "<p>Description …</p>",
    "event_start_date": "2026-07-04T19:00:00",
    "event_end_date": "2026-07-04T22:00:00",
    "event_link": "https://example.org/events/42",
    "event_image": "https://example.org/img/42.jpg",
    "event_ticket_link": "https://example.org/tickets/42",
    "event_categories": ["Music"],
    "location": "City park",
    "street": "Parkstraße 1",
    "zip_code": "12345",
    "town": "Example Town",
    "latitude": 52.52,
    "longitude": 13.40
  }
]
```

Entries with the same title and venue are merged into one event with several
dates. Import a file manually:

```bash
python manage.py import_events_json events.json <source_id>
```

Or upload it via the API (`POST /api/v4/import/upload-file/` with
`Authorization: Bearer <UPLOAD_AUTH_TOKEN>`, fields `file` and `source_id`).

## Synchronisation and deletion protection

Importers update events that changed in the source and delete events that
disappeared from the feed. Events created or edited by hand in the backend are
kept. If a feed suddenly returns nothing or far fewer upcoming events than
before, deletion is skipped and an error is recorded at the source (`import_errors`,
visible in the admin and in the monitoring).

## Duplicates

Events that appear in several sources are detected by title, start time and
venue. Which one is kept depends on the source **priority** (100 = original
source, 50 = default, 20 = aggregator) and the completeness of the entry. Details:
[duplicates.md](duplicates.md).

Maintenance commands:

```bash
python manage.py cleanup_event_duplicates     # dry run by default
python manage.py cleanup_article_duplicates --delete --days 1
python manage.py cleanup_link_duplicates
```

## Other maintenance commands

| Command | Purpose |
|---|---|
| `update_event_is_past`, `mark_events_past` | Mark past events |
| `update_event_start_dates` | Align start dates with the next occurrence |
| `consolidate_occurrences` | Merge overlapping occurrences |
| `convert_broad_occurrences` | Split implausibly long occurrences with the language model |
| `fill_event_location`, `update_eventv4_coordinates` | Venue text and geocoding |
| `tag_events_local` | Tag events with the language model |
| `select_hot_articles` | Mark the most-read article per area |
| `purge_tombstones` | Remove old deletion markers |
| `check_source_urls` | Check whether source URLs are reachable |
| `delete_events_by_source`, `remove_tags_from_events` | Bulk operations per source |
| `init_import_records` | Rebuild import bookkeeping from upload logs |
